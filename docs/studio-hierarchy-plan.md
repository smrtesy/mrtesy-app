# מנוע היצירה — היררכיית התוצרים (פרויקט → סקריפט → קול/תמונה/וידאו)

> **מה זה:** תכנון מוסכם (המשתמש, 2026-07-31) לסדר את סטודיו ההפקה כהיררכיה
> אמיתית שבה **הפרויקט הוא היחידה היחידה**, ה**סקריפט** הוא השדרה שמחלקת את
> ההפקה לשוטים, וכל שוט מחזיק תוצרים מכל הסוגים שמקושרים זה לזה. מחליף את
> "הפולדר-קול המוסתר" (דרך A) שב-`docs/studio-quick-line-plan.md` — במקום להסתיר
> שכבה טכנית, מוחקים אותה ומחברים את הסוגים ישירות. ענף:
> `claude/studio-production-expert-agent-zxqkug`.

## ההיררכיה (מה שסוכם)

```
Project  (studio_projects)              — היחידה שתמיד קיימת, בית הכול. אין "פרויקט קול"
  ├─ Voice / Image / Video (תוצרים)     — יכולים לחיות ישירות בפרויקט, עצמאיים
  │     • וידאו-מפרומפט = תוצר בלי מקורות, בלי סקריפט, בלי שוט ✓
  │
  └─ ── ארגון אופציונלי (רק בהפקה מסודרת) ──────────────────
        Script (מקור: Google Doc, אופציונלי) → Shot (קטע/קליפ, אופציונלי)
              ├─ Voice(שוט)  ┐
              ├─ Image(שוט)  ├─ מקושרים אוטומטית
              └─ Video(שוט) ⟵ source_voice_line_id + source_image_run_id
```

**קריאה:** הפרויקט הוא הציר הקבוע. הסוגים (קול/תמונה/וידאו) יכולים לעמוד לבד.
סקריפט → שוט → קישור-אוטומטי הם שכבת-ארגון שנכנסת רק כשמפיקים מסודר; אחרת אין.

**הרעיון המרכזי:** וידאו לא נוצר מהאוויר — הוא נגזר משוט מסוים: הקול של אותו
שוט + התמונה של אותו שוט. הסקריפט הוא מה שמגדיר את השוטים, ולכן כל תוצר יודע
לאיזה שוט הוא שייך ומאילו תוצרים-מקור הוא נבנה. המערכת מקשרת ביניהם אוטומטית.

## הפרויקט הוא הבית; קישור ושוט הם אופציונליים (החלטת המשתמש, 2026-07-31)

תיקון לשני ניסוחים קודמים — גם "תוצרים צפים" (לא רצוי) וגם "השוט הוא שדרה
שתמיד קיימת" (כפייה מיותרת). הנכון באמצע:

1. **הפרויקט הוא היחידה שתמיד קיימת ובית הכול.** "לא צף" פירושו: שום תוצר לא
   חי מחוץ לפרויקט בפינת-scratch מנותקת — כל תוצרי הפרויקט יושבים יחד, נגישים
   באותו מקום. זה המבנה הקבוע היחיד.
2. **יצירה עצמאית נתמכת במלואה.** אפשר ליצור **וידאו מפרומפט בלבד** — בלי קול,
   בלי תמונה, בלי סקריפט, בלי שוט. הוא יושב בפרויקט, פשוט בלי מקורות. אותו דבר
   לתמונה או קול בודדים.
3. **קישור בין תוצרים = אופציונלי.** וידאו *יכול* לשאת את `source_voice_line_id`
   + `source_image_run_id` שממנו נבנה — כשבונים אותו כך. אחרת ריק. הקישור מוצג
   כשקיים, ולא נכפה.
4. **שוט = ארגון אופציונלי, לא חובה.** "שוט" = קטע/קליפ בודד. רלוונטי רק בהפקה
   מסודרת מסקריפט, כשרוצים לקבץ את הקול/תמונה/וידאו של אותו קטע ולקשר ביניהם
   אוטומטית. אין הפקה מסודרת? אין שוט, והתוצרים חיים בפרויקט כרשימות לפי סוג.
5. **הפרדה/ניתוק לפי צורך.** כשתוצרים כן מקושרים, המשתמש יכול לנתק ידנית.

> נגזרת סכמה: `script_id`, `shot_seq`, `source_voice_line_id`,
> `source_image_run_id` — **כולם nullable ואופציונליים.** וידאו-מפרומפט = כל
> השדות ריקים. הפקה מסודרת = השדות מתמלאים ומקשרים. אין אילוץ NOT NULL חדש על
> `experiment_runs`. (טייק-קול עדיין דורש `script_id` מהסכמה הקיימת — לכן
> קול-מהיר נכנס לבאקט-קול אחד לפרויקט, שנשאר בבית ולא צף; זה מגבלת-סכמה, לא
> כפיית-מבנה.)

## מה קיים היום מול מה שחסר (מאומת מול הסכמה)

| חלק | היום | פער |
|---|---|---|
| פרויקט כללי | `studio_projects` ✓ | — |
| סקריפט | `smrtvoice_scripts` — אבל תחת **פולדר-קול** (`smrtvoice_projects`), קול-בלבד | צריך להיות תחת הפרויקט, משותף לכל הסוגים |
| שוט (יחידת-חלוקה) | אין — הסקריפט הוא רשימת שורות שטוחה (`smrtvoice_lines.line_number`) | צריך מזהה-שוט שכל הסוגים מתיישרים אליו |
| קול | `smrtvoice_lines` (`script_id`, `line_number`) ✓ | מקושר לסקריפט, לא לשוט חוצה-סוגים |
| תמונה / וידאו | `experiment_runs` (`stage`, `studio_project_id`, `derived_from`→`experiment_runs`) | אין `script_id`/שוט; `derived_from` מצביע רק על ריצה אחרת — **לא** על טייק-קול |
| קול→וידאו | — | חסר לגמרי (טבלאות שונות) |

## שינויי הסכמה המוצעים (מיגרציה אחת, forward-only)

הטבלאות כמעט ריקות (שלב פיילוט), לכן זה הרגע הנכון. טיוטת מיגרציה
`YYYYMMDDHHMMSS_studio_hierarchy.sql`:

1. **הסקריפט עולה לרמת-הפרויקט.**
   `ALTER TABLE smrtvoice_scripts ADD COLUMN studio_project_id uuid REFERENCES studio_projects(id) ON DELETE CASCADE;`
   הסקריפט הופך לשדרה של הפרויקט. `project_id` (פולדר-הקול) נשאר זמנית לתאימות
   ומאוכלס אוטומטית מפולדר-ברירת-מחדל אחד לכל פרויקט, עד שהמנוע יגמל ממנו
   (מנוע הקול קורא ממנו שפה/מודל — לא נוגעים בו בשלב הזה, כדי לא לשבור הפקה).

2. **מזהה-שוט חוצה-סוגים.** הוספת `shot_seq int` ל-`smrtvoice_lines`
   ול-`experiment_runs` — יחידת-החלוקה שכל הסוגים מתיישרים אליה תחת אותו סקריפט.

3. **קישור התוצרים ל-`experiment_runs`:**
   - `add column script_id uuid references smrtvoice_scripts(id) on delete set null`
   - `add column source_voice_line_id uuid references smrtvoice_lines(id) on delete set null`
   - `add column source_image_run_id  uuid references experiment_runs(id)  on delete set null`
   כך וידאו נושא בגלוי את שני המקורות שלו (קול + תמונה), והמערכת יודעת לשרשר.

4. אינדקסים: `(script_id, shot_seq)` על שתי הטבלאות; `source_*` על וידאו.

> אין `DROP` של `smrtvoice_projects` בשלב הזה — מחיקתו היא צעד שני אחרי שהמנוע
> יגמל מ-`project_id`. כרגע: פולדר-ברירת-מחדל **אחד** לכל פרויקט, נוצר אוטומטית,
> אף פעם לא מוצג ולא נקרא "פרויקט קול".

## השלכות UI

- **תפריט צד:** פריט חדש **"הפקה"** מתחת ל"דשבורד" (`smrtStudioItems`).
- **משטח-הפקה אחד** (`/studio/projects`): בורר-פרויקט קטן למעלה (+ יצירת פרויקט);
  מתחתיו מנוע היצירה של הפרויקט הנבחר. אין דף-רשימה כצעד-ביניים.
- **תצוגה לפי סקריפט → שוט:** התוצרים מוצגים מקובצים לפי שוט, וכל שוט מראה את
  שלושת הסוגים זה-לצד-זה (קול · תמונה · וידאו). הווידאו מציג מאיזה קול+תמונה נבנה.
- **אין "צור פרוייקט קול"** בשום מקום. הסוג נבחר בטאב; הפרויקט הוא המיכל.

## תוכנית בנייה מדורגת (כל שלב = commit, בונה על הקודם)

1. **ניווט + משטח מאוחד** (בלי סכמה): פריט "הפקה" בתפריט; `/studio/projects`
   הופך לבורר-פרויקט + `StudioProject` מוטמע; הסרת "צור פרוייקט קול" +
   פולדר-ברירת-מחדל אוטומטי מאחורי הקלעים. **ניתן לשחרר מיד.**
2. **מיגרציית ההיררכיה** (סעיף למעלה) — אחרי אישור המשתמש; לא מורץ על פרודקשן
   בלי אישור מפורש.
3. **Backend:** קריאות שכותבות/קוראות `script_id`+`shot_seq`+`source_*`; חשיפת
   התוצרים מקובצים לפי שוט עם הקישורים.
4. **UI תצוגת-שוט:** קול·תמונה·וידאו זה-לצד-זה לכל שוט, עם מקורות הווידאו.
5. **גמילה מ-`smrtvoice_projects`** (מחיקת השכבה) — צעד נפרד, אחרי שהמנוע עודכן.
