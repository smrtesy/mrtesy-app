# תכנון: חיפוש-על תוכני בכל המערכת

> טיוטה לאישור. סטטוס: **ממתין ל"גו"** — כולל אישור-עלות על voyage (סעיף "עלות").
> נכתב: 2026-07-30 (ניו יורק). ענף: `claude/split-button-system-search-6z00el`.

## 1. מה בונים ולמה

היום אין במערכת שום חיפוש חוצה-מקורות. רוצים **חיפוש אחד תוכני (סמנטי)**
שמוצא כל פרט במערכת — לא לפי חפיפת-מילים אלא לפי **משמעות** — ומציג את
התוצאות ב**טאב מלא, מקובץ לשלוש קבוצות**:

1. **הגדרות / דף במערכת** — מסכים, הגדרות ודפי אדמין (הדוגמה: "סודות" → דף
   "מפתחות וסודות").
2. **הצעה / משימה / מידע** — פריטי התוכן של המשתמש.
3. **שיחה בקלוד** — שיחות בקונסולת קלוד (הדוגמה: "בעיה בפתיחת חשבון לעובד חדש").

**דרישת-מפתח:** חיפוש **תוכני, לא לפי מילות**, ו**דו-לשוני** — מחפשים בשפה
אחת ומוצאים תוצאה בכל שפה.

## 2. ההבחנה שקובעת את הארכיטקטורה

- **מנוע-קלוד של המנוי** (`server/src/modules/claude/runner.ts`) הוא **סוכן
  אגנטי** שמריץ תהליך — מצוין וחינם, אבל **לא מנוע אחזור**: אי אפשר להאכיל
  אותו את כל ה-DB בכל חיפוש, והוא איטי מדי ללולאת-חיפוש חמה.
- אחזור-מילים בעברית ב-Postgres **חלש** (אין stemming עברי). מודל שמדרג רק
  "מועמדים שהמילים תפסו" יפספס בדיוק את המקרה חסר חפיפת-המילים — כלומר את
  ליבת מה שביקשנו.
- **המסקנה:** אחזור סמנטי אמיתי עובד דרך **embeddings** (voyage), שכבר קיים
  בקוד (`server/src/services/voyage.ts`, ורב-לשוני — לכן הדו-לשוניות בחינם).
  התפקיד הנכון של **מודל-המנוי** כאן הוא לא האחזור אלא שכבת **ההבנה/ההצגה**
  (דירוג ה-top וכתיבת "למה זה תואם") — חינם, ומחוץ ללולאה החמה.

## 3. הארכיטקטורה

### 3.1 טבלת אינדקס מאוחדת אחת

מהדרים כל מקור לטבלה אחת `search_documents`, במקום להטמיע בכל טבלה בנפרד —
כך יש אינדקס-וקטור אחד, פונקציית-match אחת, וקיבוץ טריוויאלי לפי `source_type`.
מבוססת 1:1 על התבנית שכבר עובדת ב-`knowledge_base` (pgvector `vector(1024)`,
HNSW cosine, פונקציית `match_*`):

```
search_documents (
  id           uuid PK,
  org_id       uuid,            -- לסינון הרשאות (NULL = פלטפורמה/גלובלי)
  user_id      uuid,            -- מקורות user-scoped
  source_type  text NOT NULL,   -- 'destination' | 'task' | 'suggestion' | 'info' | 'claude_thread'
  source_id    text NOT NULL,   -- מזהה הרשומה במקור (או ה-href ליעד)
  title        text NOT NULL,   -- הכותרת שתוצג
  snippet      text,            -- תקציר לתצוגה
  url          text NOT NULL,   -- הקישור העמוק שנפתח כטאב
  language     text,
  embedding    vector(1024),    -- voyage-4 של title+snippet+מילים נרדפות
  updated_at   timestamptz,
  UNIQUE (source_type, source_id)
)
```

מיפוי המקורות לקבוצות התצוגה:

| קבוצה בתצוגה | `source_type` | מקור בקוד | טקסט שמוטמע |
|---|---|---|---|
| הגדרות / דף | `destination` | אינדקס ניווט (ראה 3.3) | תווית he+en + מילים נרדפות |
| הצעה / משימה / מידע | `task` / `suggestion` | `tasks` (נבדל ב-status) | title + description |
| הצעה / משימה / מידע | `info` | `info_facts` | entity + attribute + value |
| שיחה בקלוד | `claude_thread` | `claude_threads` (+ תוכן ההודעות) | title + תקציר השיחה |

### 3.2 זרימת החיפוש

1. מטמיעים את השאילתה (קריאת voyage אחת, "query") — זניח.
2. `match_search_documents(query_embedding, p_org_id, p_user_id, …)` — חיפוש
   קרוב-שכן חוצה-מקורות, מסונן להרשאות המשתמש.
3. מקבצים את התוצאות לפי `source_type` → שלוש הקבוצות.
4. **(אופציונלי, שלב 2)** מודל-המנוי מדרג מחדש את ה-top-N ומוסיף שורת הסבר.
   נשאר מחוץ ללולאה החמה — v1 יכול לרוץ בלי זה ולהיות מהיר לגמרי.

### 3.3 אינדקס הניווט (`destination`) — נגזר, לא ידני

- **תוויות:** נקראות חי מ-`messages/{he,en}.json` → שינוי-שם של דף מתעדכן לבד,
  והדו-לשוניות מגיעה חינם (מטמיעים תווית עברית+אנגלית יחד).
- **יעדים:** נגזרים מהמקורות שכבר מתחזקים — פריטי הסיידבר ו-`APPS` registry
  (`src/lib/apps/registry.ts`, כולל תת-דפי אדמין `secrets`/`parameters`/…).
- **מילים נרדפות:** החלק הידני היחיד — קובץ אחד קטן
  (`src/lib/search/destinations.ts`), שורה ליעד ("סודות/מפתחות/טוקנים").

## 4. שמירת טריות (שלא "ירקב")

- **תוכן (task/info/claude):** אינדוקס נכתב על כל שינוי — טריגר DB או hook
  בנתיב-הכתיבה הקיים — + סקריפט backfill חד-פעמי לתוכן הקיים. מחיקת רשומה
  במקור מוחקת את שורת האינדקס (FK/טריגר).
- **ניווט (destination):** אותה תרבות של `map-guard.sh` הקיים — בדיקת-build/hook
  שחוסמת אם נוסף route בלי רשומת-יעד. מסך חדש לא יכול להישלח בלי להיות בר-חיפוש.

## 5. ה-UI

- **פיצול הכפתור** ב-`Sidebar.tsx` (דסקטופ + FAB בנייד): כפתור קלוד הגדול
  כמו היום + **איקון זכוכית-מגדלת קטן** לצדו. לחיצה → שורת-חיפוש אחת נפתחת
  (תבנית ה"מכווץ עד שצריך", רפרנס `WhatsAppReader`). Escape/X → נסגר.
- **טאב מלא:** התוצאות נפתחות כטאב (מנגנון `openTab` הקיים), מסך אחד עם
  שלוש הקבוצות — כל שורה עם כותרת, תקציר, ותג-סוג, ולחיצה פותחת את היעד
  כטאב נוסף (קישור עמוק מדויק, לא דומיין).
- **הרשאות:** האינדקס והתוצאות מסוננים למה שיש למשתמש גישה אליו (חלק מהיעדים
  super-admin בלבד).

## 6. עלות — לאישור

- **מודל-המנוי:** אפס עלות (על ה-OAuth של המנוי).
- **voyage (embeddings):** API **מדוד**, אבל **200M הטוקנים הראשונים לחשבון
  חינם** (מתועד ב-`voyage.ts`). אינדוקס כל המערכת + חיפושים שוטפים כמעט
  בוודאות בתוך המכסה החינמית → **בפועל ~$0**. נדרש **אישור-עלות מפורש** לפני
  ריצת ה-backfill (כלל אישור-העלות), למרות שהצפי הוא אפס.

## 7. מחוץ לתכולה / פתוחים

- אין type-ahead חי בכל הקלדה (חיפוש על Enter) — חוסך קריאות ומשאיר את זה מהיר.
- דירוג-מחדש ע"י מודל-המנוי (3.2 שלב 4) הוא **שלב 2**, לא v1.
- סף-דמיון (`match_threshold`) ומספר תוצאות לקבוצה — יכוונו אחרי בדיקה על
  תוכן אמיתי בעברית.

## 8. שלבי בנייה (אחרי אישור)

1. מיגרציה: `search_documents` + `match_search_documents` (תבנית knowledge_base).
2. שירות אינדוקס בבקאנד + backfill (אחרי אישור-עלות).
3. טריגרים/hooks לשמירת טריות של task/info/claude.
4. אינדקס הניווט הנגזר + קובץ המילים-הנרדפות + guard.
5. Endpoint חיפוש (`/api/search`) — embed שאילתה → match → קיבוץ.
6. UI: פיצול הכפתור + מסך התוצאות בטאב.
7. (שלב 2) שכבת דירוג/הסבר של מודל-המנוי.
