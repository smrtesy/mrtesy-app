## השלבים

### A — פרויקט מאוחד + שלד הטאבים
- מיגרציה `studio_projects` (org-scoped) + ‏`studio_project_id` ‏nullable על
  `smrtvoice_projects` (+ backfill ‏1:1) ועל `experiment_runs`. שום שאילתה
  קיימת לא נשברת (עקרון "view לפני מיגרציה" מ-`smrtstudio-plan.md` §2א).
- ‏CRUD ‏`/studio/projects` (‏requireApp) + מסך: רשימת פרויקטים → עמוד פרויקט
  עם שלושה טאבים — **קול · תמונה · וידאו** (הגדרת המשתמש; תסריט הוא תוצר
  בשלב הכתיבה, לא טאב — פתוח להרחבה). טאב קול = תצוגת פרויקט-הקול הקיים
  המקושר; תמונה/וידאו = `experiment_runs` של הפרויקט בגריד הקיים.
- עיקרון UI: קומפקטי, ברירת-מחדל מכווץ (כלל הבית).

### B — שכבת ההמלצה + טופס יצירה
- בטאב תמונה/וידאו: "צור תוצר" → בחירת סוג+סגנון → טופס מלא-מראש:
  מודל מומלץ (מ-`winner-*.json` כשקיים, אחרת מועמדי הקטלוג) · פרומפט-שלד
  מהמתכון · שדות מהסכמה החיה (מנגנון `recipes.ts` הקיים) · הכל ניתן לעריכה.
- **שורת-הרמז מהלקחים**: ‏gen-studio-recipes מסונכרן גם עם
  `troubleshooting.md`/`moves.md`; שוט עם מאפיין מתויג (סיבוב מהיר…) מציג
  רמז שקט "💡 עבד ב-…" (הפצת-לקחים בלי תהליך — הכרעת המשתמש 30/07).
- יישור קנון: ‏indexer מפסיק לקרוא fal ישירות ונטען מ-`catalog.json` שברפו
  (או מתויג כ-mirror בלבד) — ההכרעה מתוכנית-המומחה.

### C — runner ב-backend + הודעת סיום (עודכן לפי ביקורת 30/07)
- **מיגרציית פרובננס תחילה (חוסם-ביקורת 1):** ל-`experiment_runs` חסרות
  עמודות — נוספות: `endpoint_id`, ‏`input_args jsonb`, ‏`fal_request_id`
  (+אינדקס), ‏`recipe_source`, ‏`run_status` (‏pending/submitted/completed/
  failed/downloaded), ‏`error`, ‏`derived_from`, ‏`qc_cost_usd` — עם trigger
  ‏write-once (שורה קיימת לא נדרסת; הרצה-מחדש = שורה חדשה). זהו שלב-0 של
  v3 שהתוכנית דילגה עליו.
- **‏provisioning (חוסם-ביקורת 2):** ‏`FAL_KEY` נכנס למשתני ה-backend
  ב-Railway (לא קיים שם היום — אומת בקוד) · כתובת webhook ציבורית + אימות
  חתימה · **‏poller-fallback**: הרצה ב-`submitted` מעל סף-זמן נבדקת יזומות
  מול התור — webhook שאבד לא משאיר הרצה תקועה, וההורדה נעשית בתוך חלון
  ה-24ש' של קישורי fal.
- **שער-כסף מינימלי בתוך C (חוסם-ביקורת 3):** כפתור "הרץ" לא נשלח בלי
  דיאלוג-אישור: אומדן רשמי (`pricing/estimate`, מפתח רגיל) + אישור מפורש.
  בלי זה אין הרצה — כלל 2 לא ממתין ל-D.
- **אחסון (ממצא 4):** ‏bucket חדש `studio-media` (מיגרציה + RLS, בתבנית
  ‏smrtvoice-audio), מגבלת-גודל, והורדה מיידית אליו בסיום.
- ‏`POST /studio/runs`: תור fal אסינכרוני בלבד, פרובננס מלא, מקביליות
  מ-`concurrency` → webhook/poller → הורדה → עדכון → התראה (smrtTask/מסך).

### D — שכבת הכסף (החלטות המשתמש 30/07 בתוקף)
- ‏`FAL_ADMIN_KEY` בסביבת ה-backend בלבד; ‏endpoints חסומים לתפקיד מנהל
  (לא `requireApp` הגס) — ממצא הביקורת.
- צ'יפ יתרה בכותרת (צבע-מצב, פופאובר: יתרה·הוצאה·קישור-טעינה) · דיאלוג
  אישור-הרצה: אומדן רשמי (`pricing/estimate`) + יתרה-אחרי + חסימה כשאין
  קרדיט · עלות אמיתית על כרטיס ההרצה · סיכום עלויות בפרויקט + מסך רוחבי
  (פרויקט×תקופה×מודל; הקול ממקור Resemble נפרד — ממצא הביקורת) · תקציב-סבב
  ועצירת 80%.

### E — ‏QC בתצוגה + שופט-VLM מאחורי דגל (אושר 30/07)
- תצוגת ציוני ה-QC הקיימים; "טרם נבדק" כשאין (בלי worker — ההכרעה).
- שופט-VLM (‏openrouter/router/vision, רובריקה מפורקת) רץ רק על עוברים/
  גבוליים, עלות אמיתית נרשמת פר-בדיקה, עקיפה אנושית תמיד.

### F — צינור ההתייעצות (חוזה מוגדר בתוכנית-המומחה)
- כפתור "יש לי בעיה" על תוצר → משימת-התייעצות עם payload מובנה (פרובננס
  מלא) → סשן `/expert` מחזיר `{diagnosis, solutions[], rejected[]}` →
  המסך מרנדר **תיבות-סימון → הערכת-עלות מיידית → "אשר והרץ"** (UX שהוגדר).

### G — בליעת smrtVoice (אחרון, בסדר בטוח)
- הטאב עובד על אותו דאטה → הסבת ניווט/entitlement → מחיקת הקליפה. בלי
  תקופת שתי-מערכות-אמת.
