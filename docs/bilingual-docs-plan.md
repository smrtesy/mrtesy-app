# טאב מסמכים דו-לשוני + תרגום על-פי-דרישה

תוכנית בנייה. סטטוס: **ממתין לאישור "צא לדרך"**. אדמין בלבד.
מחבר: קלוד · תאריך: 2026-08-06 (ניו יורק).

## המטרה

הטאב **מסמכים** (`/admin/docs`) הופך למרכז מסמכים דו-לשוני:

1. **שני טורים זה לצד זה** — טור עברית, טור אנגלית.
2. בכל טור מופיע **שם המסמך בשפת הטור**.
3. מסמך שקיים רק בשפה אחת → בטור השני מופיע כפתור **תרגם**.
4. לחיצה על תרגם → המסמך נשלח לתרגום ב**קלוד המובנה** (מנוי, אפס טוקנים בתשלום)
   → התרגום נשמר → מוצג מיד באפליקציה.
5. **קישור עמוק פנימי** לכל מסמך — נותנים קישור לקריאה בתוך האפליקציה, לא בגיטהאב.

## החלטות שהוכרעו (עם המשתמש, 2026-08-06)

| נושא | הכרעה |
|---|---|
| איפה נשמר התרגום | **DB** — טבלה חדשה, לא קובץ ברפו (הצגה מיידית, בלי deploy) |
| הקורפוס הקיים | **לסווג** כל מסמך לשפתו; מסמך שמעורב בשתי שפות — **לפצל** למסמך לכל שפה |
| הרשאה | **אדמין בלבד** (כמו היום) |
| היקף | לבנות **הכל ביחד** |

## ארכיטקטורה

### מודל הנתונים

מסמך לוגי מזוהה ע"י **מפתח-מסמך** (`doc_key`) — הנתיב היחסי של הקובץ ברפו,
בלי סיומת שפה. לכל מסמך שני "תאים": `he` ו-`en`. תא מתמלא מאחד משניים:

- **קובץ ברפו** (`docs/**/*.md`) — מקור-האמת, בגיט.
- **תרגום ב-DB** — תוצר נגזר, מיוצר על-פי-דרישה.

מפתח-מסמך נגזר מהנתיב אחרי הסרת סיומת השפה: `docs/foo.he.md` ו-`docs/foo.en.md`
שניהם `doc_key = "docs/foo"`. קובץ בלי סיומת שפה (`docs/bar.md`) → `doc_key =
"docs/bar"`, ושפתו **מזוהה** (ראה למטה).

### זיהוי שפה + כותרת לכל שפה

- **שפת קובץ:** קידומת `lang:` ב-frontmatter אם קיימת; אחרת היוריסטיקה על התוכן
  (יחס תווים עבריים מול לטיניים בגוף, מתעלם מגושי-קוד). נגזר ב**זמן-בנייה**
  לתוך `src/generated/docs-meta.json` (המחולל כבר קיים ל-created/updated —
  מרחיבים אותו).
- **כותרת לכל שפה:** מכותרת ה-H1 הראשונה של המסמך; דריסה אפשרית ב-frontmatter
  (`title_he` / `title_en`). בתרגום — קלוד מייצר גם את הכותרת המתורגמת.

### טבלת התרגומים (מיגרציה תוספתית — הפיכה)

```sql
CREATE TABLE doc_translations (
  id           uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  doc_key      text NOT NULL,               -- הנתיב בלי סיומת שפה
  source_path  text NOT NULL,               -- הקובץ ממנו תורגם
  target_lang  text NOT NULL CHECK (target_lang IN ('he','en')),
  title        text,                         -- הכותרת המתורגמת
  content      text,                         -- ה-markdown המתורגם
  status       text NOT NULL DEFAULT 'pending'
               CHECK (status IN ('pending','running','ready','error')),
  error        text,
  run_label    text,
  source_hash  text,                         -- זיהוי שהמקור השתנה מאז התרגום
  created_at   timestamptz DEFAULT now(),
  updated_at   timestamptz DEFAULT now(),
  UNIQUE (doc_key, target_lang)
);
```

תוספתי בלבד (`CREATE TABLE`) → מוחל עצמאית דרך ה-Management API, בלי אישור.

### זרימת התרגום

1. לחיצה על "תרגם" בתא הריק → `POST /api/admin/docs/translate`
   `{ doc_key, source_path, target_lang }`.
2. השרת יוצר שורה `status='running'` ומריץ `runOneShot(prompt, { label, timeoutMs })`
   (‏`server/src/modules/claude/runner.ts:1843`) — מנוי, אפס טוקנים בתשלום.
   הפרומפט: "תרגם את מסמך ה-markdown הבא ל<שפה>, שמור על מבנה, קוד, קישורים
   וטבלאות בדיוק; החזר markdown בלבד." + כלל **שמירת קישורים כלשונם** (CLAUDE.md).
3. התוצר נשמר `status='ready'`, עם `title` ו-`source_hash`.
4. הטור מציג את התרגום; הזיהוי `source_hash != current` מוסיף תג "המקור עודכן —
   תרגם מחדש".
- **מסמך ארוך מדי לפרומפט-argv אחד** (סף ~100KB, MAX_ARG_STRLEN): מפצלים
  לפי כותרות H2 לחלקים, מתרגמים כל חלק, ומאחדים. נדיר; רוב המסמכים קטנים.
- **א-סינכרוני:** הכפתור עובר ל"מתרגם…" עם סטטוס; הטור מתעדכן ב-poll קצר עד `ready`.

### ממשק — שני טורים

- `DocsBrowser` מקבל תצוגה חדשה: רשימת **מסמכים לוגיים** (לפי `doc_key`), כל שורה
  עם שני תאים — עברית / אנגלית.
- לחיצה על שם בתא → פותח את המסמך באותה שפה. תא ריק → כפתור "תרגם".
- **קישור עמוק:** `?doc=<doc_key>&lang=<he|en>` נוחת ישר על המסמך הנכון.
  → קישור פנימי לקריאה: `https://app.smrtesy.com/he/admin/docs?doc=<key>&lang=<lang>`.
- קורא גם **תת-תיקיות** (`docs/**`), לא רק הרמה העליונה (כך שום מסמך לא נעלם).
- קישורי-הצלב במסמך מפנים **פנימה לאפליקציה**, לא לגיטהאב.

### סיווג הקורפוס הקיים (חד-פעמי, נבדק מולך)

- המחולל מזהה שפה לכל 59 המסמכים (+ תת-תיקיות).
- מסמך **מעורב** (עברית+אנגלית באותו קובץ) → מוצג ברשימה נפרדת לפיצול; הפיצול
  עצמו עורך קבצים קיימים ולכן **נעשה בבקרה מולך** (משנה קבצים + קישורי-צלב).
- מסמך חד-לשוני → מסומן בשפתו; הטור השני מציע "תרגם".

## סיכונים / פתוחים

1. **פיצול מסמכים מעורבים** — משנה קבצים וקישורי-צלב; נעשה בבקרה, לא אוטומטית.
2. **מסמך ענק** — מטופל בפיצול-לפי-כותרות; אם עדיין בעייתי — ריצת-thread מלאה במקום runOneShot.
3. **המסמך הזה עצמו** יהיה מהראשונים לקבל תרגום אנגלי דרך הפיצ'ר.

## מכאן והלאה (התנהגות קבועה)

כל מסמך שאני כותב נשמר תחת `docs/`, ואני נותן קישור **פנימי** לקריאה באפליקציה
(‏`/admin/docs?doc=...`), לא לגיטהאב.
