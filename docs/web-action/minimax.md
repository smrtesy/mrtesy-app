# פלייבוק — פתיחת חשבון מינימקס וחילוץ API key

מקרה-המבחן הראשון ל-web-action. אדפטיבי: הזרימה מגלה את הטופס מהצילומים ולא
נשענת על סלקטורים קשיחים (ה-UI של מינימקס משתנה).

## צעד 0 — האם בכלל צריך?
במערכת שלנו מינימקס מגיע **דרך fal** (`FAL_KEY`, ראה `voice-engine` ו-`video-lab`).
לפני שפותחים חשבון ישיר — ודא מול המשתמש שהוא באמת צריך מפתח מינימקס **ישיר**
(למשל שימוש ב-API של מינימקס שלא דרך fal). אם לא — עצור, זה מיותר.

## תנאים מוקדמים
- אישור-אדם ליצירת החשבון + אישור-תנאים (כלל web-action).
- מייל: החשבון נפתח על מייל שה-Gmail של המשתמש קורא (אימות אוטומטי).
- אם מינימקס דורש טלפון: השתמש במספר המחובר במערכת (`sms_connections`) כדי
  שקוד ה-SMS ייקלט אוטומטית; אחרת זה יהפוך לצומת-אדם.

## הזרימה (לפי הסקיל web-action)
1. הנפק auth וצור סשן (ראה SKILL).
2. נווט לעמוד ההרשמה של פלטפורמת מינימקס (אתר ה-API/הפלטפורמה, לא אפליקציית
   הצריכה). קבל את ה-URL המדויק מהמשתמש או מדף-הבית של מינימקס.
3. צלם → זהה את שדות ההרשמה (מייל/סיסמה/טלפון) → מלא ב-`act fill`.
4. שלח את הטופס (`act click` על כפתור ההרשמה).
5. **אימות מייל:** `GET /verification/email?from=minimax` (או הדומיין בפועל) →
   נווט ל-`link` או מלא `code`.
6. **אימות טלפון (אם יש):** `GET /verification/sms` → מלא `code`.
7. **CAPTCHA (אם יש):** עצור, בקש מהמשתמש לפתוח `/web-action`, "קבל שליטה",
   לפתור, ולאשר — ואז המשך.
8. אחרי כניסה: נווט לאזור ה-API keys בדשבורד, צלם, מצא/צור מפתח.
9. שמור בוואלט: `POST /vault/api-key` עם `label:"MiniMax API key"`,
   `secret:<KEY>`, `url:<פלטפורמת מינימקס>`, `username:<email>`. **בלי להדפיס את המפתח.**
10. סגור סשן. דווח: נפתח חשבון, המפתח נשמר בוואלט (בלי הסוד), ומה נדרש אדם.

## הערות
- אם מינימקס דורש תשלום/כרטיס להנפקת מפתח — **עצור ואשר עם המשתמש** (תשלום
  תמיד אדם + אישור-עלות).
- אם ההרשמה האוטומטית נחסמת שוב ושוב (anti-bot) — אל תילחם; הצע שהמשתמש יפתח
  את החשבון ידנית, ו-web-action ימשיך מחילוץ-המפתח בלבד.
