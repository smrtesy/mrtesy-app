# תוכנית — סוכן-פעולה באינטרנט (פתיחת חשבונות, חילוץ מפתחות → וואלט)

מסמך לאישור. היכולת: אתה מתאר משימה ("פתח חשבון חינם ב-X, קח את ה-API key,
שמור בוואלט"), Claude מבצע אותה בדפדפן **אוטונומית ככל האפשר**, ועוצר לנקודות-
אדם רק בקירות אנטי-בוט (CAPTCHA / אימות-טלפון / תשלום). חל על **mrtesy-app**.

## עיקרון: אוטונומי-מקסימלי, בלי עקיפת-הגנות

"אוטונומי ככל האפשר" = לדחוף כל שלב שאפשר לאוטומציה, אבל **לא לבנות עקיפת
CAPTCHA/SMS** (שירותי פתרון, מיילים חד-פעמיים) — זה מפר תנאי-שימוש, שביר,
ומסכן חסימה. לכן גם במקסימום-אוטונומיה יש **נקודות-אדם** בקירות. הגבול המוסרי:
מפעילים את **החשבונות שלך**, מעדיפים **API רשמי** כשקיים, בלי התחזות/עקיפה.

## מה אוטומטי ומה דורש אדם

| שלב | מצב |
|---|---|
| מילוי טופס ההרשמה (שם, מייל, סיסמה) | **אוטומטי** |
| **אימות-מייל** | **אוטומטי** — המערכת כבר קוראת Gmail (`server/src/services/gmail`); Claude מוצא את מייל האימות ולוחץ על הקישור/מחלץ את הקוד |
| **אימות-טלפון/SMS** | **אוטומטי** — קוד ה-SMS נכנס למערכת (`/sms/webhook` → טבלת `sms_messages`); Claude שולף את הקוד האחרון למספר המחובר ומזין. תנאי: ההרשמה משתמשת במספר שמחובר במערכת (`sms_connections`) |
| חילוץ ה-API key מהדשבורד + שמירה בוואלט | **אוטומטי** |
| הנפקת מפתחות דרך API רשמי (כשקיים) | **אוטומטי** — מסלול מועדף |
| **CAPTCHA / reCAPTCHA** | **אדם** — **הקיר האנושי היחיד שנשאר** (ראה למטה) |
| **תשלום / הזנת כרטיס** | **אדם** — לעולם לא אוטומטי, גם אם אפשר |

## הקיר האנושי היחיד — CAPTCHA

אימות-מייל **וגם** אימות-SMS **אוטומטיים** (שניהם נכנסים למערכת — Gmail
ו-`sms_messages` — ו-Claude שולף את הקוד). לכן הקיר האנושי היחיד שנשאר הוא
**CAPTCHA אינטראקטיבי**, שדורש שתראה ותיגע בדפדפן החי. הדפדפן רץ headless על
הקונטיינר המרוחק; אתה בצ'אט. שתי דרכים, בשתי פאזות:

- **פאזה 1 (בלי live-view):** Claude ממלא הכל עד הקיר — כולל אימות מייל+SMS
  אוטומטית. אם צץ CAPTCHA — **עוצר, מצלם, ומבקש שתשלים את הצעד הבודד הזה**
  (או שתפתח את החשבון ידנית ותיתן ל-Claude להמשיך מחילוץ-המפתח). ספק בלי
  CAPTCHA → **מקצה-לקצה אוטומטי לגמרי**.
- **פאזה 2 (live-view אינטראקטיבי):** Chromium ב-headful עם **צפייה חיה
  אינטראקטיבית** (noVNC / CDP screencast) שאתה פותח בקישור, רואה את Claude נוהג,
  **ותופס את העכבר/מקלדת רק ב-CAPTCHA** — Claude ממשיך אוטונומית משם. זה מה
  שסוגר גם את הקיר האחרון. זו הבנייה הכבדה, והשאלה הפתוחה שלה: איפה ה-live-view
  נגיש לך (URL מהקונטיינר המרוחק).

## ארכיטקטורה (נשען על מה שקיים)

1. **מצב דפדפן חיצוני (לא מוגבל-לאפליקציה).** ה-`browser-helper` הנוכחי מקובע
   ל-appUrl; גלישה חיצונית כבר קיימת בקוד (`server/src/modules/admin/domain-tracker.ts`,
   `price-tracker/extract.ts`, וה-page-check שבניתי) — נבנה מצב דפדפן חופשי-URL
   על אותו `playwright-core` + Chromium המותקן מראש.
2. **מנוע אוטונומיה** — ניווט/מילוי/חילוץ מונחה-מטרה, עם אינטגרציית Gmail
   לאימות-מייל, ומחלץ-מפתח (זיהוי שדה-המפתח בדשבורד).
3. **נקודות-אדם** — אימות מייל **וגם** SMS אוטומטיים (Gmail + `sms_messages`);
   הצומת האנושי היחיד הוא ה-live-view ל-CAPTCHA (פאזה 2); **תשלום תמיד אדם**.
4. **כתיבה לוואלט** — `smrtvault_credentials` + Supabase Vault (מוצפן במנוחה,
   service-role בלבד, מבוקר ב-`smrtvault_access_log`). המפתח נשמר כסוד-Vault;
   השורה מחזיקה רק label/url/מצביע. **קיים — לא בונים מחדש.**
5. **API-רשמי-קודם** — לכל ספק בודקים אם יש הנפקת-מפתח תכנותית; אם כן, זה
   המסלול (תואם-תנאים), והדפדפן הוא נפילה-לאחור.

## אבטחה ותנאים (קשיח)

- **סודות:** מפתחות נכנסים ל-Supabase Vault דרך השרת בלבד; לא נכתבים ללוג,
  לא לקובץ, לא ל-`.env`. כל חשיפה נרשמת ב-`smrtvault_access_log`.
- **אישור-אדם** לכל צעד לא-הפיך: יצירת חשבון, אישור-תנאים, כל תשלום.
- **תואם-תנאים:** מעדיפים API רשמי; מפעילים חשבונות שלך; בלי עקיפת-הגנות.
- **עלות:** עבודת Claude על המנוי — חינם. אם ספק דורש תשלום — עוצר ומאשר (כלל
  אישור-העלות).

## הכרעות (נעולות)

- **פאזה 2 מלאה** — live-view אינטראקטיבי, כדי לסגור גם את קיר ה-CAPTCHA.
- **מינימקס נחוץ** — הוא מקרה-המבחן הראשון (חשבון ישיר, לא רק דרך fal).

## החלטת-התשתית הקריטית: איפה הדפדפן חי

קונטיינר ה-Claude Code המרוחק **אפמרי ולא נגיש מבחוץ** (אין URL נכנס), אז
live-view אינטראקטיבי לא יכול לחיות עליו. לכן הדפדפן-ה-headful חי על **ה-backend
של Railway** (כבר יש בו Chromium — `domain-tracker`; כבר נגיש בכתובת ציבורית):
- **מנהל-סשן-דפדפן** ב-`server/` שמפעיל Chromium headful ומחזיק סשן חי.
- **CDP screencast → WebSocket** אל **מסך מאומת באפליקציה** (`/web-action` או בתוך
  `/vault`), שם אתה **רואה את Claude נוהג ותופס עכבר/מקלדת ל-CAPTCHA** (ממסר-קלט
  חזרה דרך CDP). מאובטח כמו כל מסך: `requireAuth+requireOrg`.
- Claude (הסשן/ה-runner) נוהג את הסשן דרך API של ה-backend; פאזה 1 (עצירה-בקיר)
  היא אותה תשתית בלי שכבת ה-live-view.

## שלבי מימוש

1. **מנהל-סשן-דפדפן ב-backend** — הפעלת/סגירת Chromium headful, ניווט חופשי-URL,
   מילוי/לחיצה, צילום. (מודל: `domain-tracker.ts`.)
2. **חילוץ-קוד אוטומטי** — מ-Gmail (מייל-אימות) ומ-`sms_messages` (SMS), שליפת
   הקוד האחרון למספר/כתובת הרלוונטיים.
3. **כתיבה לוואלט** — API key ל-Supabase Vault דרך smrtVault, שורת
   `smrtvault_credentials` + לוג.
4. **מסך live-view + ממסר-קלט** — CDP screencast ל-WebSocket, מסך מאומת, תפיסת-שליטה
   אנושית ל-CAPTCHA (פאזה 2).
5. **מנוע האוטונומיה + סקיל `web-action`** — משימה מונחית-מטרה, נקודות-אישור
   (יצירת-חשבון/תנאים/תשלום), עם **מינימקס כזרימת-הרצה ראשונה**.
