# שער הבטיחות לאוטונומיה של קלוד-באפליקציה

מסמך תכנון לאישור. מתאר איך קלוד-באפליקציה (התהליך שרץ ב-backend דרך
`runner.ts`) מקבל אוטונומיה לעבוד על הקוד — ואיפה עובר הקו האדום.

## העיקרון

**מה שהפיך → אוטונומי. מה שבלתי-הפיך או נוגע בפרודקשן → שער אכוף-בקוד.**
לא הבטחה בפרומפט — הדלת שדרכה קלוד פועל פשוט לא מחזיקה את היכולת המסוכנת עד
שהתנאי מתקיים.

## החלטת המשתמש (2026-07-30)

- **מיזוג ל-main:** אוטונומי — **אחרי** שפרוטוקול לפני-הדחיפה עובר נקי.
- **מיגרציה ל-DB של הפרודקשן:** תמיד **בקליק אנושי**, עם תצוגת ה-SQL.

## שלוש הדרגות

| דרגה | פעולות | שער |
|---|---|---|
| 🟢 חופשי | קריאה, עריכה, `build`/בדיקות/lint מקומיות, commit, דחיפה ל-`claude/…`, פתיחת PR | אין — הכל הפיך, ענף = Preview בלבד |
| 🟡 עלות | כל פקודה ששורפת טוקני API בתשלום | חסום עד אישור-עלות מפורש (הכלל הקיים) |
| 🔴 קו אדום | מיזוג ל-main · מיגרציה לפרודקשן | אכוף-בקוד (למטה) |

## איך כל קו אדום נאכף בקוד

### 1. מיזוג ל-main — "אוטונומי אחרי פרוטוקול", אבל הפרוטוקול נאכף בשרת

הבעיה: "פרוטוקול עבר" זו טענה של המודל. הפתרון: **ה-backend מריץ את הבדיקה
בעצמו לפני שהוא ממזג**, ולא מאמין למודל.

זרימת המיזוג (endpoint ייעודי, לא פקודת git חופשית של המודל):
1. קלוד עובד על ענף `claude/…`, דוחף, ומבקש מיזוג ל-main דרך ה-endpoint.
2. ה-backend, בעצמו: `git fetch origin main` → מיזוג origin/main לענף →
   **`npm install && npm run build`** → אם ה-build נכשל, עוצר ומחזיר את
   הכשל לקלוד (אין מיזוג). זו האכיפה: אין "עברתי" בלי build ירוק בשרת.
3. אם עבר: מיזוג `--no-ff` ל-main, דחיפה, ואז **אימות עצמי** ש-Production
   התקדם (סעיף 2 — Railway/Vercel). אם לא התקדם → התראה.

מה שנשאר "אמון": הגְרֶפִּים וסקירת סוכן-המשנה (שלבים 2-3 בפרוטוקול). את אלה
קלוד מריץ ומדווח; ה-build הוא השער הקשיח שאי אפשר לזייף.

### 2. מיגרציה לפרודקשן — קליק, תמיד

- קלוד **כותב** את קובץ המיגרציה על ענף (`supabase/migrations/…`) — חופשי.
- **החלה** על ה-DB עוברת דרך תור-אישורים: קלוד יוצר בקשה עם ה-SQL המלא;
  המסך מציג לך את ה-SQL ומה הוא משנה; אתה לוחץ **"הרץ מיגרציה"** — ורק אז
  ה-backend מחיל. תואם את "Migration discipline" ב-CLAUDE.md (אין החלה על
  פרודקשן בלי אישור אנושי מפורש).

## מעקות בטיחות נוספים

- **הפעלת מעטפת:** כדי שהדרגה 🟢 תעבוד בכלל, קלוד-באפליקציה מקבל הרשאת הרצת
  פקודות בהרצה חסרת-ראש (allowedTools מוגדר לפקודות עבודה: git מקומי, build,
  בדיקות). זה מה שמסיר את "חלון האישור שלא רואים".
- **תקרת רקורסיה:** לדלת ה-M2M שקלוד קורא לה יש מגבלת עומק — הוא לא יכול
  לשרשר את עצמו אינסוף.
- **בלי כסף לבד:** קלוד לא יכול להפעיל הרצות-בתשלום (fal/API) בלי אישור-עלות,
  גם בתוך פקודת מעטפת.
- **Fail closed:** כל שגיאה/ספק בשער → ברירת המחדל "לא בוצע".

## מה נבנה (בכפוף לאישור)

1. הפעלת הרצת פקודות לקלוד-באפליקציה (allowedTools בהרצה).
2. endpoint מיזוג-ל-main שמריץ build בשרת לפני המיזוג + אימות דיפלוי.
3. תור-אישורים למיגרציות + מסך "הרץ מיגרציה" עם תצוגת SQL.
4. תקרת רקורסיה ומגן בלי-כסף-לבד לדלת ה-M2M.
5. חיבור Railway/Vercel (סעיף 2) לאימות הדיפלוי העצמי — דורש טוקנים ממך.
