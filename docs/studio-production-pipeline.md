# מנוע ההפקה — הליך ההפקה ומודל-התוצרים המאוחד

> **מה זה:** חשיבה רחבה (המשתמש, 2026-07-31) על סידור הסטודיו לפי **הליך
> ההפקה האמיתי** של דרמה/דיבוב מונפש. מרחיב ומחליף את `docs/studio-hierarchy-plan.md`
> (שהיה נכון אך חלקי): המבנה אינו עץ אלא **גרף-גזירה** — תוצר נשען על כמה תוצרים
> אחרים. אין יותר smrtVoice כמושג-מוצר; הכול smrtStudio. ענף:
> `claude/studio-production-expert-agent-zxqkug`.

## הליך ההפקה (בסדר-תלות אמיתי)

```
1. דמות
   (א) יצירת הדמות — הזהות/העיצוב.
   (ב) סט-זוויות (turnaround) — הדמות בכל זווית אפשרית → רפרנס לאחידות בין שוטים.
2. רקעים ופריטים
   כל אחד אולי גם דורש סט-זוויות/פרטים מלא (אותו עיקרון של אחידות).
3. סטוריבורד (לכל שוט)
   פריים-מפתח שמורכב מ:  הדרכת-הסקריפט לשוט  +  דמויות (סט-הזוויות)  +  רקעים/פריטים.
4. וידאו (לכל שוט)
   נוצר מפריים(י)-המפתח של השוט  (+ קול, ללוחות ליפסינק).  ← תלוי-מודל (ראה למטה).
5. קול (לכל שורה/שוט)
   טייק האודיו שמזין ליפסינק או מונח מעל.
```

## התובנה המרכזית — זה DAG, לא עץ

תוצר אחד נגזר מ**כמה** מקורות מסוגים שונים:
- **סטוריבורד** ← N דמויות + M רקעים + הדרכת-סקריפט.
- **וידאו** ← 1–2 פריימי-סטוריבורד + טייק-קול.
- **סט-זוויות** ← הדמות המקורית (מקור אחד, שיטת-אחידות).

לכן שני עמודים בטבלה (`source_voice_line_id` + `source_image_run_id`) **לא מספיקים** —
צריך יחס **רבים-לרבים** של מקורות. זה הלב של המודל החדש.

## מודל-הנתונים המאוחד (smrtStudio-native, מוותר על smrtvoice כשכבת-מוצר)

**`studio_artifacts`** — שורה אחת לכל תוצר, מכל סוג:

| עמודה | תיאור |
|---|---|
| `id`, `org_id`, `studio_project_id` | זהות + הפרויקט (היחידה הקבועה) |
| `type` | `character` \| `character_angle` \| `background` \| `prop` \| `storyboard` \| `voice` \| `video` \| `lora` \| `control` (וידאו הוא גם סוג-**מקור**, לא רק תוצר-סופי) |
| `parent_id` | לסט-זוויות: `character_angle` → ה-`character` שלו |
| `script_id`, `shot_seq` | מיקום במבנה (אופציונלי — תוצר עצמאי משאיר null) |
| `angle` | לזווית: front/three-quarter/side/back… |
| `output_url`, `status`, `model`, `cost_usd`, `prompt`, `seed`, `meta` | התוצר עצמו |

**`studio_artifact_sources`** — קשתות ה-DAG (רבים-לרבים):

| עמודה | תיאור |
|---|---|
| `artifact_id` | התוצר הנגזר |
| `source_artifact_id` | המקור |
| `role` | `character` \| `background` \| `prop` \| `start_frame` \| `end_frame` \| `keyframe` \| `video_source` \| `audio` \| `reference` \| `lora` \| `control` |

כך "וידאו ← keyframe_start + keyframe_end + voice" ו"סטוריבורד ← 3 characters + 1 background"
נשמרים במדויק, וניתוק = מחיקת קשת. **קישור כברירת-מחדל, ניתוק לפי צורך** (כמו שסיכמנו).

## ספריות-נכסים לכל פרויקט

דמויות/רקעים/פריטים הם `studio_artifacts` ברמת-הפרויקט (בלי `shot_seq`), **רב-פעמיים** בין
שוטים. דמות = הזהות + סט `character_angle` (ה-turnaround). יצירת סט-זוויות = אצווה על-פני
הזוויות בשיטת-אחידות (reference image / IP-adapter / seed קבוע), לפי סכמת-המודל.

## המפתח: מיפוי חריץ-סכמה → נכס — כך זה עובד עם **כל** סוגי מודלי-הווידאו

> **מתוקן (2026-07-31, מאומת מול הקטלוג):** הניסוח הקודם ("שוט + keyframes מכסה
> הכול") **שגוי**. בדיקה על 28 מודלי-הווידאו שעברו probe-סכמה (מתוך 462; 434 טרם
> נבדקו) הראתה מצבי-קלט שאינם keyframe: **video-to-video (14/28!)**, אודיו (3/28,
> ובקטלוג המלא 19), LoRA (10/28), וקלטי-קונטרול בשדות גנריים. keyframes הם רק
> חלק. האבסטרקציה הנכונה רחבה יותר.

**האבסטרקציה: לא "keyframes" אלא "חריץ-קלט של המודל → נכס-פרויקט מסוג ותפקיד תואמים".**
חלון-היצירה קורא את **סכמת-ה-fal החיה של המודל הנבחר** (כבר קיים ב-`/studio/recommendation`)
וממפה כל חריץ-קלט לנכס. **מודל מכתיב את החריצים — לא אנחנו.** מיפוי מלא:

| חריץ-הקלט של המודל | תפקיד (`role`) | ממופה לנכס |
|---|---|---|
| טקסט (prompt) | — | הדרכת-הסקריפט של השוט |
| תמונת-פתיחה | `start_frame` | keyframe[0] (סטוריבורד) |
| תמונת-סיום | `end_frame` | keyframe[last] |
| כמה פריימי-מפתח | `keyframe` | keyframes[0..n] |
| **וידאו-קלט** (v2v/הארכה/restyle/upscale) | `video_source` | **וידאו קיים** של השוט/פרויקט |
| אודיו/ליפסינק | `audio` | טייק-הקול של השוט |
| תמונת-רפרנס (עקביות דמות/סגנון) | `reference` | סט-זוויות של דמות / נכס-רקע |
| **LoRA / משקולות** | `lora` | נכס-משקולות של הפרויקט (דמות/סגנון) |
| קונטרול (pose/depth/mask/camera) | `control` | מפת-קונטרול (נכס) |

מודל שלא צריך פריים פשוט לא מציג בורר-פריים; מודל video-to-video מציג בורר-וידאו; וכו'.
אפס הנחות קשיחות. **נגזרת קריטית למודל-הנתונים:** `studio_artifacts.type` חייב לכלול
**`video` כמקור** (לא רק כתוצר-סופי), וגם `lora`/`control` — אחרת אי אפשר להזין
מודל video-to-video או מודל-עם-LoRA. טבלת-הקשתות `studio_artifact_sources.role`
נושאת את כל התפקידים בטבלה למעלה.

**סייג-אמינות:** רק 28/462 סכמות נבדקו. לכן המערכת **לא** מקודדת רשימת-מצבים קשיחה —
היא קוראת את סכמת-המודל בזמן-ריצה, כך שגם מצב שלא ראינו עדיין (מודל 435) עובד ברגע
שהסכמה נטענת. אינדוקס-סכמה מלא (משימת ה-indexer) ישפר את הדיוק של ההמלצות, לא את הנכונות.

## נתיב מיגרציה (בטוח, מדורג)

1. **טבלה מאוחדת + קשתות-מקור** (`studio_artifacts`, `studio_artifact_sources`).
2. **Backfill** של `experiment_runs` (image/video) → `studio_artifacts`.
3. **מנוע-הקול (החלטה פתוחה):** או שכל טייק שמופק נרשם *גם* כשורת `studio_artifacts`
   (type=voice) שמצביעה לרשומת-המנוע — המנוע לא משתנה; או מיגור מלא של המנוע בהמשך.
4. **ספריות-נכסים** (דמות + סט-זוויות, רקעים/פריטים).
5. **סטוריבורד** — הרכבה מונחית-סכמה (בורר דמויות+רקעים per shot).
6. **וידאו** — מ-keyframes + קול, עם מיפוי-החריצים למעלה.
7. **גמילה מ-smrtvoice** כשכבת-מוצר (השמות/המסכים).

## הכרעות (ננעלו ע"י המשתמש, 2026-07-31)

1. **מנוע-הקול: מיגור מלא** — לא שיקוף. הקול עובר לטבלאות ה-studio החדשות.
   **אבל לפני נעילת התוכנית — לבדוק מה כבר נבנה לקול בסטודיו** (שלב-G, נתיבים,
   טבלאות, סקריפטים) כדי לא לשבור עבודה קיימת. ← ביקורת-מלאי בעבודה.
2. **רקעים/פריטים: תלוי — נגזר מהנתונים.** מה באמת שימושי למודלי-הווידאו? נחתך
   מ**המיפוי המלא** (משימת הכיסוי המלא למטה): אם מודלים צורכים רפרנס-רקע מרובה-זווית
   → סט-זוויות; אם רפרנס יחיד מספיק לרובם → מתחילים ביחיד. החלטה מבוססת-קטלוג, לא ניחוש.
3. **סטוריבורד: הרכבה אוטומטית** — ה-AI מסדר דמות+רקע לפי הדרכת-הסקריפט. צריך
   לתכנן את מנגנון-ההרכבה (ראה למטה — נושא פתוח לתכנון).
4. **סקריפט: גם וגם.** מתחילים ממה שקיים — **Google Document** כמקור. בהמשך הסקריפט
   הופך ל**תוצר שנוצר כאן** (type בטבלה). המודל תומך בשניהם: `script` יכול להצביע
   ל-Google Doc *או* להיות תוצר מקומי.

## משימה פתוחה — כיסוי ומיפוי מלא של סכמות-המודלים

**מצב נוכחי (מאומת):** ה-probe (`POST /studio/models/index`, super-admin, חינם)
בדק **28/462** מודלי-וידאו, ולוכד רק 4 דגלים (start/end image, video_input, audio).
**"מיפוי מלא" דורש שניים:**
1. **הרחבת ה-probe** ללכוד את **כל שדות-הקלט** של כל מודל (לא 4 דגלים) — עמודה
   `input_schema jsonb` + דגלים עשירים (`lora`/`control`/`reference`/`camera`),
   כדי שמיפוי חריץ→נכס יהיה מלא וניתן-לשאילתא.
2. **הרצת סוויפ מלא** על כל ~1394 המודלים (חינם, קורא רק סכמות). הרצה = super-admin;
   מתבצע פעם אחת אחרי פריסת הרחבת-ה-probe.

תוצר: התפלגות מצבי-הקלט על **100%** מהקטלוג (לא מדגם), וזה מזין את הכרעה #2 (רקעים).
